# @chatic/logger

플랫폼 중립 로깅 코어. 웹 JS·RN/TS·순수 네이티브에서 나온 로그를 계약 하나(`LogEntry`)로 모으고,
서버로 갈 미전송 큐와 그것을 비우는 스케줄러, 성능 예산 리포터를 함께 둔다.

세 가지만 기억하면 된다.

- **`dependencies: {}`다.** DOM·React Native·MMKV·Firebase 어느 것도 import하지 않는다. 플랫폼
  동작은 전부 `LogListener`나 포트(`LogStoreReader`·`LogStoreWriter`)의 어댑터로 바깥에 배선한다.
  UUID조차 자급한다 — 워크스페이스에 `uuid`가 있어도 끌어오지 않는다.
- **저장소는 하나다.** 미전송 큐뿐이다. 진단용 링버퍼는 폐지됐고, 디버그 뷰와 업로더가 같은 큐를
  읽는다. "나중에 조회"는 없으므로 **로그를 보는 방법은 hub 구독뿐**이고, 구독보다 먼저 나온
  엔트리는 어디에도 남지 않는다.
- **hub를 구독하는 것은 리스너뿐이다.** 업로더도 모니터도 구독자가 아니라 저장소를 읽는다. 새
  소비자가 생기면 기존 리스너를 고치지 말고 하나를 더 구독시킨다 — 그때 만족해야 할 계약이
  아키텍처 문서에 있다.

문서 정본은 `docs/` 두 편이다.

- [architecture.md](./docs/architecture.md) — 파이프 전체. 계약·리스너·큐·업로더·크래시 경로,
  그리고 지금 모양이 되기까지 무엇이 사라졌는지.
- [perf-metrics.md](./docs/perf-metrics.md) — 부팅·전환·웹바이탈 측정치가 같은 파이프를 타는 방식과
  성능 예산 5개.
