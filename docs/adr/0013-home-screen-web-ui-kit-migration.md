# 홈 화면: web-ui-kit 마이그레이션 — 접기 가능한 2섹션 + 접속유형·구독 인지 헤더

## Status

accepted

결정일: 2026-07-15

## Context

`libs/web-ui-kit`가 PR #370로 출시되며 Figma 기반 컴포넌트가 갖춰졌다 — `AppHeader`,
`ListSection`/`SectionHeader`, `ListRow`, `PlaceAvatar`/`ChatAvatar`/`CloudAvatar`,
`UnreadBadge`/`VerifiedBadge`, `SubscriptionButton`, `BottomSheet`, `EmptyState`.
그런데 홈 화면(`apps/web/src/app/features/home`)은 아직 마이그레이션되지 않았다.
헤더·`PlaceList`·`ChannelList`가 lucide 아이콘과 하드코딩 hex 색상(`#F41F52`,
`#102346`)으로 손수 작성돼, 이미 kit에 존재하는 컴포넌트를 중복 구현하고 있다.

UI 리디자인이 Figma에 반영됐다. 참조 프레임(파일 `ViwLfjc5Eoq7BpEXFfFj3W`):

- `2899-22022` — 중계/기본: 로고 헤더, 플레이스 1개 `기본 플레이스`, Chat 목록
- `2675-14545` — Chat `＋` 팝오버(`1:1 대화` / `그룹 방 만들기 [PRO]`)
- `2899-20903` / `2899-21186` — 우측 프로필 → 드롭다운(`프로필 / 알림 / 설정`)
- `2931-8611` — **플레이스 다중** 클라우드(세로 목록, 선택=✓, 미읽음=점)
- `3086-13128` — 초대 클라우드 접속(클라우드명 헤더, `초대받은 플레이스`)
- `2870-21093` / `2933-9794` / `2933-10249` — 리디자인된 클라우드 전환 시트

주요 요구사항(요청 원문 기준):

- **접속 유형**(중계=Default Cloud vs 클라우드)과 **구독 여부**(free/pro)에 따라
  상태가 다르다.
- 헤더 좌측: 중계 → 브랜드 로고, 클라우드 → 클라우드 이름 + 클라우드 프로필.
- 헤더 우측: **플레이스(사이트) 프로필**, 클릭 시 메뉴가 열린다.
- 플레이스와 채널은 **펼치기/접기** 가능.
- 기본 플레이스 = 중계서버 전용 플레이스. 클라우드는 자신의 플레이스를 나열하고,
  플레이스 선택 시 그 플레이스의 채널을 노출한다.
- 검색은 **아직 미구현(TBD)**.

요청의 "아코디언"은 목업과 대조해 명확히 했다 — Slack식 플레이스별 중첩 트리가 아니라
**Place·Chat 두 섹션이 각각 독립적으로 접히는 구조**다. 모든 상태는 기존 홈 훅에
그대로 매핑된다(`useHomePlaces`, `useSwitchPlace`, `useHomeChannels`,
`useActiveCloudChannels`, `useChannelUnreads`, `resolveHeaderProfile`).

## Decision

**범위: 홈 화면을 `web-ui-kit`로 마이그레이션하고, 정말로 없는 프리미티브만 라이브러리에
새로 추가한다.** 데이터 흐름·훅·동기화 등록 모델·라우트 대상은 보존한다 — 리라이트가
아니라 프레젠테이션 계층 마이그레이션이다.

### 헤더 — `AppHeader` 채택

- 중계/Default Cloud → `kind="no-cloud"`(DoU 로고 + 전환 chevron).
- 클라우드 → `kind="cloud"`(클라우드 아바타 + 클라우드 이름 + 전환 chevron). 이름
  아래 line2에 `<플레이스 닉네임>`(`AppHeader.subName`) 슬롯이 있으나 현재 목업에선
  hidden — 선택적으로 노출.
- 좌측 chevron(`onSwitcher`) → 클라우드 전환 시트를 연다.
- 우측 클러스터: `planTier` 배지(`free`/`pro`, 구독에서 파생) → 구독 화면, 검색
  버튼(`onSearch`)은 **TBD 플레이스홀더**로 렌더, 프로필 아바타는 **플레이스(사이트)
  프로필** 표시(닉/썸네일은 `resolveHeaderProfile`이 이미 Default Cloud에선 계정,
  그 외에선 사이트 프로필로 해석).
- 프로필 아바타 → **드롭다운 메뉴**(`프로필 / 알림 / 설정`), 직접 네비게이션이 아님.
  `프로필` → 프로필 설정(기본 클라우드 밖=사이트 프로필 편집, 기본 클라우드=계정 편집),
  `알림`/`설정`은 기존 라우트로 연결.
- 현재의 `⋮` 오버플로우(이슈 신고)와 클라우드 오류 배너는 홈에서 **제거/간소화**한다.
  이슈 신고를 유지한다면 설정 하위로 이동.

### Place 섹션 — 접기 가능한 세로 목록

- 접기 가능한 섹션(`SectionHeader` + 접기 토글 chevron).
- 세로 플레이스 **행**: `PlaceAvatar` + 이름 + 서브타이틀(`기본 플레이스` /
  `내 플레이스` / `초대받은 플레이스`). 선택된 플레이스 = 파란 ✓, 미선택+미읽음
  플레이스 = 빨간 점(`unreadByPlace`에서 파생).
- **단일 활성 모델 유지**: 플레이스 선택 시 `useSwitchPlace`(backend active-site
  전환)를 호출하고, 그 채널이 Chat 섹션에 렌더된다. 클라우드는 여러 플레이스를 나열할
  수 있고, 중계는 기본 플레이스 1개만 보인다.
- 섹션 하단 `＋ 플레이스 추가` 행은 **소유자 전용**이다. 목업상 중계(`2899`)와
  초대 클라우드(`3086`)에선 hidden, 소유 클라우드(`2931`)에서만 visible — 기존
  `permissions.canCreatePlace` 게이팅과 일치한다. 중계는 기본 플레이스 1개만 보이고
  추가 행이 없다.

### Chat 섹션 — 접기 가능한 목록 + 컨텍스트 인지 `＋` 팝오버

- 접기 가능한 섹션(chevron 토글).
- 최상단에 **`MY / 나와의 채팅` self 행**이 항상 온다. 목업 확인 결과 `MY` 배지는
  중계·클라우드(초대 포함) **모든 모드**의 self 행에 표시되며 시간·미읽음이 없다
  (현재 코드의 `currentWSS === 'relay'` 게이트는 이 디자인 기준으로 너무 좁으므로
  구현 시 재확인 필요).
- 일반 채널 **행**: `ChatAvatar` + 이름 + 멤버수 배지 + 마지막 메시지 미리보기 +
  시간 + `UnreadBadge`.
- `＋` → **접속 유형에 따라 항목이 하나만 나오는 팝오버**:
    - 중계 → `1:1 대화`만.
    - 클라우드(소유자 **또는** 초대받은자) → `그룹 방 만들기`만.
- `그룹 방 만들기`는 **PRO 게이팅**: 미구독 → 기존 구독 유도 다이얼로그, 구독 →
  기존 `CreateChannelDialog`.
- `1:1 대화` → **TBD**: 버튼은 배치하되, 친구 선택 플로우는 이번 작업에서 구현하지
  않는다.

### 클라우드 전환 시트 — 시각만 리스킨, 로직 보존

- 신규 Figma로 리스킨(`BottomSheet`): `내 클라우드` / `초대된 클라우드` 탭, 서브타이틀
  있는 행(소유=계정/이메일, 초대=`OO님의 클라우드`), 선택 ✓, `＋ 클라우드 추가`. 상단
  프로필 섹션은 **제거**(프로필이 헤더 드롭다운으로 이동했으므로).
- **기존 동작 전부 보존**: 프로비저닝 폴링/배지, 클라우드 이름 편집, 연결끊기/로그아웃,
  계정 추가, 초대 클라우드 전환.

### 신규 `web-ui-kit` 컴포넌트

라이브러리에 추가(홈에서 사용, 재사용 가능):

- **접기 가능한 섹션** — `SectionHeader`에 펼치기/접기 어포던스(chevron 회전 +
  콘텐츠 표시/숨김) 추가, 접기 상태는 host가 제어.
- **헤더 프로필 드롭다운**과 **`＋` 생성 팝오버**는 기존 `DropdownMenu` 프리미티브로
  host에서 조합한다. 스펙 단계에서 kit으로 승격할 만한 재사용 형태가 보이면 그때 승격.

## Considered Options

- **Slack식 플레이스별 중첩 아코디언**(각 플레이스 행이 자기 채널을 펼침, 다중 동시
  펼침) — 기각: 목업(`2931-8611`)은 선택된 플레이스 하나가 단일 Chat 목록을 구동하는
  구조이고, 모든 플레이스의 채널을 동시에 fetch/sync해야 해 현재의 active-site 단위
  데이터 흐름을 깨뜨린다.
- **우측 프로필 클릭 시 프로필 설정 화면 직행**(원문 그대로) — 기각, Figma 드롭다운
  (`프로필/알림/설정`)을 채택. `프로필`은 여전히 설정 화면에 닿고, 드롭다운이 디자인이
  요구하는 알림/설정 진입점을 추가한다.
- **`＋` 팝오버가 항상 두 항목 노출, 게이팅만**(목업 `2675`) — 기각, 확정 규칙(접속
  유형별 단일 항목: 중계→1:1, 클라우드→그룹)을 채택.
- **클라우드 전환 시트 로직까지 재설계** — 기각: 시각만 리스킨. 프로비저닝/편집/연결끊기
  로직은 핵심이며 이번 범위 밖이다.
- **손수 만든 홈 컴포넌트 유지** — 기각: 이번 마이그레이션이 없애려는 드리프트(중복
  아바타/배지, 하드코딩 색상)의 원천이다.

## Consequences

- 홈이 하나의 디자인 시스템에서 렌더된다. 향후 디자인 조정은 홈의 개별 마크업이 아니라
  kit을 바꾼다. 하드코딩 색상과 중복 아바타/배지 코드가 제거된다.
- 헤더가 접속 유형 + 구독으로 완전히 데이터 구동된다. 동일한 `AppHeader`가 중계·소유
  클라우드·초대 클라우드 상태를 모두 서빙한다.
- 접기 가능한 섹션이 재사용 가능한 kit 프리미티브가 된다.
- `1:1 대화`와 검색은 보이지만 동작하지 않는 상태(TBD)로 남는다. 의도된 것이며, 둘 다
  범위 밖의 플로우(친구 선택, 검색)가 필요하다. 눌러도 아무 일 없는 것처럼 보이는 죽은
  버튼이 아니라 명백한 플레이스홀더여야 하고, 후속 작업으로 추적한다.
- **확인 필요 가정:** `2870-21093`/`2933-*`에서 시트 뒤에 보이는 기어 아이콘 클라우드
  헤더는 홈 헤더가 아니라 _다른 화면_(플레이스 상세/설정)으로 간주한다 — 홈은 프로필
  아바타 헤더(`2931-8611`/`3086`)를 쓴다. 구현 전 확인할 것.
- `useSwitchPlace` 보존은 플레이스 선택 시 여전히 backend active-site 전환(기존
  계약대로 낙관적)이 일어남을 뜻한다. 미선택 플레이스의 미읽음 점은 이미 존재하는
  `useActiveCloudChannels` 집계에 올라탄다.
