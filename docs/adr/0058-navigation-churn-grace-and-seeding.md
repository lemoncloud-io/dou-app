# ADR-0058: 화면 전환 churn 제거 — sync 유예, 옵저버 유예 보존, 채널 시드

> 상태: Accepted · 결정일: 2026-08-15

## 맥락 (Context)

2026-08-14 홈 요청 폭주 감사에서 [ADR-0057](0057-home-last-chat-preview-single-query.md)(홈 프리뷰 단일 쿼리)이 제거한 것은 폭주의 최대 단일 기여자였고, 나머지 절반은 **화면 전환이 모든 구독과 sync 타깃을 파괴했다가 곧바로 재생성하는 구조** 자체였다:

1. **sync 타깃**: `SyncManager.unregister`가 refs 0에서 즉시 `stopSync`하고, scheduler의 `stop`은 타깃과 **스냅샷을 함께 폐기**한다. 재등록은 `start()`의 `scheduleNow(0)`로 **즉시 폴링** 1회를 만들고, 스냅샷 부재로 첫 응답이 **무조건 "변경됨"** 판정되어 캐시 쓰기 → 리이밋 → 재조회 연쇄를 만들었다. 방↔홈 사이클마다 채널 N + 조인 N 타깃이 이걸 반복했다 (`save:channel` 228, `save:join` 632).
2. **옵저버 그룹**: `BaseLocalDataSourceV2.registerObserver`가 마지막 구독자 이탈 시 그룹(과 캐시값)을 즉시 삭제해, 재진입한 화면의 모든 구독이 저장소를 새로 읽었다 — 네이티브에서는 읽기 하나가 브릿지 왕복 하나다.
3. **입장 오류**: `useChannel`의 10초 resolve 타이머가 혼잡 시 브릿지 큐 지연(max 15초 관측)보다 먼저 만료되어, **캐시에 채널이 멀쩡히 있는데도** 오류 화면을 냈다.

## 결정 (Decision)

### 1. sync 타깃 unregister에 30초 유예 (`UNREGISTER_GRACE_MS`)

refs가 0이 되어도 즉시 stop하지 않고 지연 타이머를 건다. 유예 내 재등록은 `register`의 기존 merge 경로로 **살아 있는 타깃에 합류**한다 — 즉시 폴링도, 스냅샷 소실로 인한 무조건 쓰기도 없다.

- 유예 중 폴링은 idle 백오프(최대 60초)를 이어가므로 잔여 비용은 타깃당 요청 한두 건.
- **활성 클라이언트 교체 시 유예 엔트리를 purge한다.** 이월하면 재등록이 merge 경로로 빠져 새 클라이언트에서 `startSync`가 영영 없거나, 떠난 화면의 타깃이 새 소켓에서 폴링을 재개한다 — 둘 다 잘못이다.
- 떠난 채널(멤버십 상실)의 폴링이 최대 30초 더 살지만, 403/404 2회 → `gone` 자동 stop 경로가 기존대로 닫는다.

### 2. 옵저버 그룹 유예 보존 + 쓰기 무효화 (`RETIRED_GROUP_TTL_MS` 60초, 상한 256)

마지막 구독자가 떠난 그룹을 값과 함께 60초 보존한다. 유예 내 재구독은 저장소 대신 그룹의 값을 즉시 받는다(첫 구독의 `hasValue` 분기 그대로).

**낡은 값은 구조적으로 불가능하다**: 유예 중인 그룹에 해당하는 쓰기가 flush에 걸리면 재조회하는 대신 **그룹째 버린다** — 듣는 이 없는 재조회는 낭비이고, 남겨둔 값은 오답이 되기 때문. 따라서 유예에서 되살아난 값은 언제나 "마지막 구독자가 보던 것과 같고 그 뒤로 아무 쓰기도 없었던" 값이다. stale-while-revalidate를 두지 않은 이유: 무효화-삭제만으로 신선도 보장이 공짜고, 재검증 기계는 복잡도만 더한다.

### 3. 홈 행 → 방 채널 시드 (표시 전용)

`ChannelItem`이 navigation state로 자기 channel row를 넘기고(`openThread`가 `rootChat`을 넘기는 전례), `useChannel`이 이를 `seed`로 받아 **관측 해소 전까지의 표시**를 채운다. 시드가 있으면 10초 resolve 타이머는 오류 화면으로 넘어가지 않는다(화면에 내용이 있는데 오류로 바꿔치우는 것이 타이머의 원래 목적보다 나쁘다).

시드는 해석 의미론을 건드리지 않는다: `hasResolvedRef`는 옵저버 소유 그대로라 콜드 캐시의 첫 `null`은 여전히 "fetch 진행 중"이고(부재 오판 → 홈 바운스 회귀 방지), **해소된 제거**(행이 있다가 사라짐)는 시드보다 이겨서 호출부의 이탈 처리가 산다.

### 4. `PlaceChannelManagePage`도 리스트 레벨 `useLastChats`로 전환, `useLastChat` 폐지

행별 구독의 마지막 소비자가 사라졌으므로 훅을 삭제했다. 프리뷰 판정 단위 케이스는 `libs/data`의 `chatPreview.test.ts`로 이식.

## 결과 (Consequences)

- 방↔홈 사이클: 즉시 폴링 2N발 → 0, 스냅샷 소실 쓰기 2N → 0, 재진입 브릿지 재조회 대부분 → 그룹 캐시 히트. 입장 오류 화면은 시드 있는 진입에서 소멸.
- 유예의 대가: 화면을 완전히 떠난 뒤에도 타깃 폴링이 ≤30초, 그룹 값 보존이 ≤60초(쓰기 없을 때만) 지속된다 — 측정된 폭주 대비 의도적으로 지불하는 상수 비용이다.
- `SyncManager`/`BaseLocalDataSourceV2`의 계약 테스트가 새 의미론("dispose는 유예 후 stop", "재구독은 유예값 즉시 수신")으로 갱신되었다.
