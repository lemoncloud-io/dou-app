# 채널 설정 화면 개편 — web-ui-kit 재정비 + 프로필 상세/알림 설정 신규(UI-only)

## Status

accepted

결정일: 2026-07-16

## Context

채널 설정 관련 화면이 DoU 디자인으로 리디자인됐다(Figma 파일 `ViwLfjc5Eoq7BpEXFfFj3W`).
반영 대상은 세 축 — **채팅방 설정 · 채팅방 정보 수정 · 프로필 상세** — 이며, 부수적으로
확인 다이얼로그, 알림 설정, 인원 상한 안내가 포함된다.

코드 현황(작업 전):

- **채팅방 설정**은 이미 존재한다 — [ChannelSettingsPage.tsx](../apps/web/src/app/features/channels/pages/ChannelSettingsPage.tsx).
  소유자 분기(`channel.isOwner` = `ownerId === myUid`)·방이름 편집·초대·삭제/나가기·
  멤버목록(소유자/MY 뱃지)이 이미 구현돼 있으나 새 디자인은 미반영이다.
- **채팅방 정보 수정**도 이미 존재한다 — [UpdateChannelDialog.tsx](../apps/web/src/app/features/channels/components/UpdateChannelDialog.tsx).
  풀스크린 라우트가 아닌 **in-page Dialog**이며, 방이름 + **썸네일 업로드까지 이미 동작**한다.
- **프로필 상세("친구 정보")는 존재하지 않는다.** 컴포넌트·라우트 전무, `MemberListItem`도
  클릭 불가 → 완전 신규.
- **알림 설정 화면도 없다**(과거 stub 제거, README 참조).

백엔드 제약(핵심): `ChannelRepositoryV2`에 **멤버별 별명(nick) 쓰기·알림 설정 뮤테이션이
없다.** 현재 존재하는 쓰기는 `createChannel`/`updateChannel`/`inviteChannel`/`leaveChannel`/
`deleteChannel`뿐이다.

단, **멤버 추방(kick)은 `leaveChannel`로 가능**하다 — `ChannelLeaveRequestData`가
`{ channelId, userId? }`이므로 `userId`를 넘기면 해당 멤버를 내보낸다(userId 생략 시 본인
나가기). 소유자만 수행. 주의: 현재 `leaveChannel`은 `channelId`만 보고 **내 로컬 캐시에서
채널을 무조건 evict**하므로, kick(=타 userId)일 때는 evict하지 않도록 분기가 필요하다.

## Decision

### 범위 (포함)

1. **채팅방 설정 재스타일** — 기존 `ChannelSettingsPage`를 새 Figma에 맞춰 재정비.
   소유자/일반 멤버 분기는 **기존 `channel.isOwner`를 그대로 재사용**한다(신규 판별 로직 없음).
2. **채팅방 정보 수정 재스타일** — 기존 `UpdateChannelDialog`(name + thumbnail)를 유지하고
   스타일만 개편. 저장 성공 토스트 반영.
3. **프로필 상세("친구 정보") 신규** — **in-page Dialog**로 구현(기존 `UpdateChannelDialog`
   패턴 계승, 라우트 추가 없음). 진입점은 설정 화면 **멤버목록 항목 탭**.
    - 소유자 분기는 **방 소유자 기준(`channel.isOwner`)** — 소유자 뷰(2935-23247)는 ⋯메뉴에
      `친구 삭제` 추가, 일반 뷰(2935-23150)는 `신고하기`만. 이름은 양쪽 다 읽기 표시.
    - **별명(닉네임) 편집은 미구현** — 백엔드 미비로 이번엔 편집 input·`완료` 버튼을 두지 않는다.
      이름은 읽기 표시만.
    - **`친구 삭제`(kick)는 실제 연동** — 소유자만, `leaveChannel({ channelId, userId })`.
      `leaveChannel` 캐시 evict를 self-leave에만 적용하도록 분기 추가(위 Context 주의).
4. **알림 설정 신규** — **in-page Dialog**로 구현. 진입점은 설정 화면 `알림` 액션 버튼.
5. **확인 다이얼로그 재스타일** — 방 삭제/나가기(`ConfirmDialog`) 문구·스타일을 디자인에 맞춤.
6. **인원 100명 초과 안내 얼럿** — 초대 흐름의 클라이언트 가드로 추가.
7. **컴포넌트는 `@chatic/web-ui-kit` 기반** — 누락 컴포넌트는 라이브러리에 신규 정의 후 사용.
   stateless·slot·i18n-agnostic 라벨 props·토큰 사용·`*.test.tsx`+`*.stories.tsx` 동반 원칙
   (ADR-0010/0013 계승).

### 미연동(UI-only) — 표시·버튼만, 데이터 연동 없음

백엔드 메서드가 없어 다음은 **표시/버튼만** 둔다(재진입 시 로컬 상태 초기화 허용):

- **알림 설정** — 메시지 알림 토글(로컬 상태만), 앱 알림 꺼짐 배너.
- **신고하기** — 프로필 상세 ⋯메뉴 버튼.

(`친구 삭제`는 연동으로 승격, **별명 편집은 미구현으로 제외** — 위 Decision 3 참고.)

### 범위 (제외)

- 멤버별 별명 쓰기·알림 설정의 **실제 데이터 연동**(백엔드/repository 신규 필요).
- **별명(닉네임) 편집 UI 자체**(편집 input·완료 버튼) — 백엔드 미비로 이번 범위 제외, 후속.
- 읽음 계산 등 그 외 데이터 계층 로직 변경(kick을 위한 `leaveChannel` evict 분기는 예외로 포함).
- 신규 URL 라우트(프로필 상세·알림 설정 모두 Dialog).
- **1:1 채팅 전용 레이아웃**(Figma 2957-10970 · 2970-13420 · 2970-13653 · 2970-12918 ·
  2970-13693 · 2948-30128 · 2988-10929 · 2987-10924) — 섹션 리스트형 설정, 인라인 알림
  토글, 닉네임 설정형 프로필, 플레이스 연동 나가기 등은 **1:1 채팅 전용**이라 이번 범위에서
  제외한다. 이번 작업의 최종 기준은 첫 배치 11개 프레임(위 Context 표)이다.

## Alternatives

- **신규 라우트 방식** (`/channels/:id/members/:uid` 등) — 딥링크/뒤로가기엔 유리하나
  `paths.ts`·라우팅 신규가 필요하고 기존 정보수정 Dialog 패턴과 불일치. minimal 위배로 버림.
- **별명/친구삭제/알림 풀 연동** — 백엔드 스펙 협의가 선행돼야 하고 일정·범위가 크게 늘어남.
  UI-only로 두고 백엔드 준비 시 후속 ADR에서 재방문.
- **`JoinStereo === 'owner'` 기반 소유자 판별** — 모델엔 존재하나 UI는 이미 `ownerId === myUid`를
  쓰고 있어 불필요. 기존 파생 유지.

## Consequences

- **얻는 것**: 세 화면이 새 디자인으로 일관되게 정비되고, web-ui-kit 자산이 확충된다.
  소유자 분기·정보수정·초대/삭제/나가기 등 검증된 로직을 재사용하므로 리스크가 낮다.
- **트레이드오프**: 미연동 버튼(신고·친구삭제·별명편집·알림)은 사용자에게 "동작하지 않는 UI"로
  보일 수 있다 → 토스트 안내 또는 명시적 비활성 처리로 기대치를 관리해야 한다. UI-only 토글/입력은
  로컬 상태만 가지므로 재진입 시 초기화된다. 백엔드가 준비되면 이 지점들을 다시 방문한다.
