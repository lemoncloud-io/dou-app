# Observe 탭 실시간 디바이스 동기화 — 요구사항

> 2026-07-08 · feature/socket-lab · 상위 시스템: [socket-lab](../socket-lab/00-requirement.md)

## 배경

Observe 탭(User Watchlist)은 유저를 관측 대상으로 추가해 디바이스 상태(green/yellow/red, tick, viewing)를 보는 관제 화면이다.
현재는 HTTP presence 조회를 수동(유저 클릭·reload 버튼)으로만 갱신하므로, 디바이스 상태 변경을 실시간으로 확인할 수 없다. "LIVE" 배지가 있으나 실제 라이브가 아니다.

## 원문 요구사항

- 관측하고 있는 디바이스 상태 변경에 따른 실시간 확인이 필요함
- 어드민에도 WS 연결 기반의 지속 동기화 전략이 필요함
- HTTP 기반 고빈도 폴링은 고려사항이 아님

## 기능 요구사항 (FR)

1. **자동 동기화**: 관측 중인 모든 유저의 모든 디바이스 상태가 주기적으로 자동 갱신된다. 상태 변경 후 화면 반영까지 체감 지연은 수 초 이내(동기화 주기 수준).
2. **연결 상태 가시화**: WS 연결 상태 배지(연결됨/연결 중/끊김)와 마지막 동기화 시각을 화면에 노출한다. 죽은 데이터를 라이브로 오인하지 않게 한다.
3. **스테이지 연동**: 기존 d1/v1 스위칭과 정합 — dev/prod WS는 별개 서버이므로 첫 진입 시 둘 다 연결해 두고, 전환은 뷰 스왑만으로 즉시 이루어진다. 비활성 스테이지의 관측 대상도 계속 동기화되어 전환 즉시 최신 데이터를 본다.
4. **삭제 전파**: 이 화면에서 디바이스를 삭제하면 즉시 동기화 대상에서 제외되고 목록에서 사라진다. 다른 경로로 삭제된 디바이스는 디바이스 목록 재조회 시점에 반영된다.
5. **신규 디바이스 발견**: 관측 유저에게 새 디바이스가 붙으면 저주기(60초) 목록 재조회로 발견되어 동기화 대상에 편입된다.
6. **유저 presence 집계**: 유저 단위 presence·SummaryStrip 집계도 디바이스 상태 변경에 따라 갱신된다.

## 서버 제약 (확인된 사실)

- 디바이스 상태 변경 시 서버는 **해당 디바이스의 커넥션으로만 유니캐스트** — 어드민 커넥션은 push 수신 불가. 동기화는 pull로만 가능.
- since 기반 delta 조회 미지원 — pull은 디바이스 단위 전체 상태 조회(`device.read`)뿐.
- 삭제된 디바이스를 read하면 에러가 아닌 **stale view가 반환**됨 — pull로는 삭제 감지 불가.
- WS 연결마다 디바이스 등록(`device.save`)은 필요하나, read만 하는 경우 auth.update(토큰 인증) 없이 동작 — 익명 커넥션으로 타 유저 디바이스 read 가능.
- WS 엔드포인트: dev = `…/cht-d1?v2`(현 `VITE_WS_ENDPOINT`), prod = 동일 호스트 `…/cht-v1?v2`.

## 제약·스코프 밖

- **lemon-model(PR #8) sync-machine 도입은 이번 스코프에서 제외** — 별도 검증 트랙으로 분리 (사유는 plan 문서의 critic 검토 결과 참조).
- 서버 push(멀티캐스트/어드민 구독) 도입은 서버 로드맵 사항. 단, 추후 push가 생겨도 클라 구조 변경 없이 수용 가능해야 한다.
- Probe 탭 인벤토리(`deviceApi.ts`)의 스테이지 전환은 별도 건.
- 오프라인 저장, 변경 이력 타임라인은 비목표.

## 수용 기준

- [ ] 관측 유저의 디바이스에서 상태(tick/status/viewing) 변경 발생 시, 조작 없이 화면에 반영된다 (주기 + α 이내).
- [ ] WS가 끊기면 배지가 즉시 비연결 상태를 표시하고, 재연결 시 동기화가 재개된다.
- [ ] 첫 진입 시 d1/v1 WS가 모두 연결되고, d1↔v1 전환은 재연결 없이 즉시 해당 스테이지의 최신 관측 데이터를 보여준다.
- [ ] 이 화면에서 삭제한 디바이스는 pull이 중단되고 목록에서 사라진다 (유령 재시도 없음).
- [ ] 관측 디바이스 수가 상한을 넘으면 유저 추가가 거부되고 사유가 안내된다.
- [ ] 마지막 동기화 시각이 표시되고, 백그라운드 탭 등으로 지연되면 그 시각으로 staleness를 확인할 수 있다.

## 후속 검토 (이번 구현 밖)

- **서버 보안**: 익명 WS 커넥션으로 임의 디바이스 id의 상태·viewingId를 read할 수 있는 현재 동작은 IDOR성 노출 소지 — 서버 측 검토 필요. 어드민 도구가 이 동작에 의존하므로, 차단 시 어드민 인증 경로(auth.update)를 함께 제공해야 한다.
- 어드민 관측 세션이 등록하는 디바이스 레코드(유령 디바이스)의 서버 측 정리 방침(TTL 등).
